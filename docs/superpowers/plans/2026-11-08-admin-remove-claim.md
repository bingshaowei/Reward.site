# 管理员移除承接人实施计划

依据：本聊天中用户确认并要求实现的《管理员移除承接人方案》。仅本地实现与验收，不推送、不部署。

1. 增量迁移009与后端：管理员移除、必填原因及私密元数据、不扣分、禁止重领、独立待验收成果终止、团队保留成果或全员移除后补招、指定名单追加及审计。事务沿用钱包锁→任务锁。
2. 权限与历史：统一更新名额、当前参与资格、成果/附件访问、工作台；交付时保存团队参与成员快照，防止重组后新成员获取旧团队的私有成果。
3. 前端：管理员移除确认弹窗、已移除成员记录、原因按后端可见性展示、指定人选补位、工作台移除状态。
4. 验证：权限、原因边界与隐私、扣分、待验收终止、团队剩余一人/全员移除/待修改、指定补位、附件访问、重复请求及并发验收；全量测试、类型检查、正式构建和本地浏览器验收。

默认规则：原因去空白后1～2000字；记录不可被重复请求覆盖；旧奖励不撤销；旧扣分不返还；不发送邮件；不删除文件。新成员不得通过旧团队记录获得附件权限，被移除者保留本人上传的交付和附件。
